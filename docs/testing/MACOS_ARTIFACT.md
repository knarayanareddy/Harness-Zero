## Blocking shutdown finding

After the successful browser context closes, SIGTERM reaches the native daemon
and prints its shutdown message. It does not exit within the probe's10-second
cleanup bound. The original owned process group is force-killed; the sandbox port
is initially still open and `daemon.json` remains. A subsequent listener check
confirms both ports closed. The forced stop is not graceful-shutdown success.

An independent actual-source HTTP/EventBus probe isolates the cause: no-SSE stop
completes in0.001s, while a disconnected EventSource leaves `stop()` pending beyond
1s. Publishing a labeled cleanup notice wakes the handler and allows cleanup to
finish. The pre-fix handler waits for its15-second heartbeat; its `stop()` waits on
HTTP cleanup without explicitly stopping owned stream handlers. The bounded repair
must own/close those handlers, not increase the probe limit or lower heartbeats.
Its separate default regression and source review remain required before rebuilding.

removes daemon metadata. In a second fresh process, withholding only its owned

process exits0 in0.813s with both ports closed. Thus the resource smoke gate can
fail for the real missing-resource condition, and the shutdown failure is scoped
