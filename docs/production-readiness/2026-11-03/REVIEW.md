# Harness-Zero — static review

## Scope and verdict

**Stage:** implemented agent harness, with explicitly experimental components; not a production-readiness assessment. Pinned `main` revision: `bfa52425c1ff37536f31dc74df2ed66dcd953e58`. The sampled web authentication and streaming paths expose consequential trust-boundary gaps. Prioritize local access control, sensitive output handling, and verification of the complete tool path before broader deployment.

This is a targeted static sample, not a complete audit. **Runtime, installation, builds, tests, live services, browser and OS sandbox checks were NOT RUN** under the review mandate. The snapshot's tree inventory is not evidence that every file was read. Four supplemental read-only requests retrieved pinned `harness/frontends/web/server.py`, `harness/kernel/gate.py`, `.github/workflows/ci.yml`, and selected matching lines from `tests/frontends/test_web_server.py`. See the evidence inventory for limits.

## Architecture and product boundary

The packaged entry points `harness` and `harness-zero` both target [`harness.cli:main`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/pyproject.toml#L29-L31); the frozen binary entry imports the same function ([`engine_main.py:7–15`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/engine_main.py#L7-L15)). The web server registers command, event, and artifact routes ([`server.py:270–278`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/frontends/web/server.py#L270-L278)); the gate validates tools, invokes policies, then handlers ([`gate.py:496–524`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/kernel/gate.py#L496-L524), [`gate.py:641–674`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/kernel/gate.py#L641-L674), [`gate.py:903–915`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/kernel/gate.py#L903-L915)). Plugin trust and OS privileges matter: the security policy explicitly states plugins are in-process trusted Python and share host privileges without external isolation ([`SECURITY.md:113–115`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/SECURITY.md#L113-L115)). Provider, executor, storage and protocol implementations were not traced end to end.

## Findings ledger

**HZ-01 — High, confirmed static: public bootstrap hands out the master credential.** The auth guard marks GET `/` and `/ui` public ([`server.py:141–161`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/frontends/web/server.py#L141-L161)). `_handle_index` substitutes `"__HARNESS_TOKEN__"` and sets `"harness_token"` to `self.auth_token` ([`server.py:334–357`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/frontends/web/server.py#L334-L357)); that cookie is accepted for protected requests ([`server.py:174–178`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/frontends/web/server.py#L174-L178)). A local process able to reach the loopback listener can obtain a credential intended to protect command routes. The documented single-user model limits the assumed attacker; this is not proof of remote exploitation. Require an authenticated, user-bound bootstrap, preserve usability without handing arbitrary local clients a master token, and independently verify the resulting OS boundary.

**HZ-02 — High, confirmed static exposure path; downstream filtering unverified: streaming precedes gate sanitization.** `emit_output_delta` publishes `text=text` directly to the bus ([`gate.py:296–311`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/kernel/gate.py#L296-L311)); final text sanitization happens later ([`gate.py:1025–1056`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/kernel/gate.py#L1025-L1056)). The server serializes subscribed events into SSE ([`server.py:506–516`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/frontends/web/server.py#L506-L516)). Whether bus or producer paths independently redact was not inspected; an actual leak is **not demonstrated**. Trace every producer and subscriber, test synthetic secrets split across chunks, and sanitize before publication, including metadata and persisted output.

**HZ-03 — Medium, confirmed static: SSE tickets are not route-scoped.** The middleware accepts and consumes `"ticket"` for any non-public route ([`server.py:180–191`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/frontends/web/server.py#L180-L191)), although the issuer describes it as a `"single-use ticket for EventSource / SSE"` ([`server.py:325–332`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/frontends/web/server.py#L325-L332)). A stolen unused ticket can therefore have broader authority than its stated purpose, including a command request if other checks permit. Bind tickets to GET `/events`, expiry and intended session; test rejection elsewhere and replay.

**HZ-04 — Medium, confirmed static: existing daemon file permissions are not repaired.** `os.open(... O_CREAT | O_TRUNC, 0o600)` writes the token ([`server.py:639–654`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/frontends/web/server.py#L639-L654)); the creation mode does not tighten an already-existing permissive file. The impact depends on filesystem and prior state; no leakage was measured. Use a safely created, non-symlinked restrictive file and verify existing-file behavior and ownership before writing secrets.

**HZ-05 — Medium, confirmed static gap: changed tool arguments are not revalidated in the inspected path.** Schema validation occurs before hooks ([`gate.py:519–525`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/kernel/gate.py#L519-L525)); hooks and policies can update `current_args` afterward ([`gate.py:636–639`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/kernel/gate.py#L636-L639), [`gate.py:665–681`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/kernel/gate.py#L665-L681)), which reaches the handler ([`gate.py:903–912`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/harness/kernel/gate.py#L903-L912)). No malicious plugin exploit is asserted: plugins are trusted, and policy ordering and concrete schemas require further review. Revalidate final arguments and ensure all safety policies evaluate the final immutable call.

**HZ-06 — Low, historical CI / dependency integrity risk.** The [CI run at the pinned SHA](https://github.com/knarayanareddy/Harness-Zero/actions/runs/39082591345) is recorded as successful in the snapshot, not rerun here. The workflow uses movable major action tags and installs Python requirements ([`ci.yml:18–36`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/.github/workflows/ci.yml#L18-L36)); Python dependencies have lower bounds rather than exact versions ([`pyproject.toml:10–24`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/pyproject.toml#L10-L24)). The snapshot includes a Node lockfile; it was not audited. Reproducibility and advisory status remain unverified, not a claim of a known CVE.

Keyboard, screen-reader, error recovery and approval clarity remain unverified.

## Production blockers and owner questions

Do not expand access until HZ-01–05 are reproduced, corrected or explicitly risk-accepted. Owner must decide supported local-user and untrusted-plugin threats, permitted providers/credentials, sandbox fallback policy, release/signing platform, transcript retention and recovery objectives. A responsible-disclosure contact is listed as `security@harness-zero.local` ([`SECURITY.md:128–138`](https://github.com/knarayanareddy/Harness-Zero/blob/bfa52425c1ff37536f31dc74df2ed66dcd953e58/SECURITY.md#L128-L138)); owner should verify a reachable private channel rather than assume delivery. No certification is implied.
